# YandexDL — локальная галерея и менеджер скачивания Яндекс.Диска

Проект собирает метаданные всех фото и видео с вашего Яндекс.Диска (через прозрачный перехват трафика), строит из них локальную галерею с превью и умеет скачивать файлы обратно — фото пачками, видео с восстановлением повреждённых участков.

Всё локально: `127.0.0.1`, данные лежат в SQLite-базах и папке `server/files/`.

---

## Как это работает

```
Браузер ──(системный proxy 127.0.0.1:8000)──> mitmproxy + capture/addon.py
                                                    │
                       перехват ответов models-v2?m=photo-get-clusters-with-resources
                       + сохранение кук/sk/User-Agent
                                                    │ POST /api/ingest, POST /api/auth
                                                    ▼
                                        server/server.py  (Flask, 127.0.0.1:8001)
                                                    │
                     ┌──────────────────────────────┴──────────────────────────────┐
                     ▼                                                             ▼
             gallery.db  (метаданные)                                    auth.db (куки, sk)
             галерея /  + /status                                        ссылки для видео
                     │                                                             │
                     ▼                                                             ▼
        очередь фото (HTTP, размеры ORIGINAL…XXXS)      очередь видео (recover.py + ffmpeg)
                     ▼                                                             ▼
                 server/files/                                              server/files/
```

1. **Перехват** — `capture/addon.py` читает ответы Яндекса на `models-v2?m=photo-get-clusters-with-resources` (то, что браузер запрашивает при прокрутке ленты «Фото») и пересылает JSON на локальный сервер. Ответ клиенту не меняется, аддон только читает.
2. **Авторизация** — из тех же запросов аддон забирает `Cookie`, токен `sk`, `connection_id`, `User-Agent` и обновления `Set-Cookie`, кладёт их в отдельную базу `auth.db`. По ним сервер сам запрашивает прямые ссылки на скачивание видео (`models-v2?m=mpfs/url`).
3. **Галерея** — `server.py` пишет всё в SQLite, отдаёт сетку по дням с подгрузкой и превью (Pillow + pillow-heif для HEIC).
4. **Скачивание фото** — воркеры качают размеры по очереди `ORIGINAL → XXXL → … → XXXS`, с очередью, таймаутами, автостопом при серии ошибок.
5. **Скачивание видео** — отдельная очередь запускает `recover.py` (через `recover_runner.py`, чтобы обойти системный прокси): качает файл блоками, битые участки заменяет нулями, чинит начало MP4 и пересобирает через `ffmpeg`.

## Структура

```
YandexDL/
├── capture/
│   └── addon.py              # mitmproxy-аддон: перехват метаданных + авторизации
├── server/
│   ├── server.py             # Flask-сервер: приём данных, галерея, очереди скачивания
│   ├── recover.py            # автономный качалка/чинилка видео (stdlib, + ffmpeg)
│   ├── recover_runner.py     # обёртка recover.py: игнорирует системный прокси и сертификат
│   ├── requirements.txt
│   ├── gallery.db            # создаётся при первом запуске — метаданные
│   ├── auth.db               # создаётся при первом запуске — куки/sk
│   ├── files/                # скачанные файлы
│   └── thumbs/               # превью
└── README.md
```

## Требования

| Что | Зачем |
|---|---|
| Python 3.8+ (3.11+ рекомендуется) | сервер и аддон |
| mitmproxy | прозрачный перехват HTTPS-трафика Диска |
| Pillow + pillow-heif | превью и открытие HEIC в галерее |
| ffmpeg в PATH | сборка/ремонт видео и видео-превью |
| 2 терминала | сервер и mitmdump работают одновременно |

## Установка

### 1. Скачать исходники

Распаковать архив, открыть терминал в папке проекта.

### 2. mitmproxy

```bash
# macOS
brew install mitmproxy

# Debian/Ubuntu
sudo apt install mitmproxy
```

Windows: скачать и установить с https://www.mitmproxy.org/

### 3. Python

```bash
# macOS
brew install python

# Debian/Ubuntu
sudo apt install -y python3 python3-pip python3-venv
```

Windows (PowerShell от администратора):

```powershell
winget install Python.Python.3.14
```

### 4. Сертификат mitmproxy

Нужен для перехвата HTTPS. Инструкция: https://docs.mitmproxy.org/stable/concepts-certificates/

Коротко: запустите `mitmdump`, откройте `http://mitm.it` в браузере через прокси, скачайте сертификат для своей ОС и установите его в системное хранилище (macOS — в «Служебные ключи», затем `security add-trusted-cert`/«Доверять»; Linux — `sudo cp mitmproxy-ca-cert.pem /usr/local/share/ca-certificates/ && sudo update-ca-certificates`; Windows — двойной клик → «Установить сертификат» → «Доверенные корневые центры»).

### 5. Перезагрузка

Перезагрузить систему (или перезапустить браузер), чтобы сертификат и настройки точно применились.

### 6. Зависимости сервера

```bash
cd server
pip install -r requirements.txt     # (не "pip install requitements.txt")
```

Лучше в виртуальном окружении:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

Нужны **два терминала одновременно**.

**Терминал 1 — сервер:**

```bash
cd server
python3 server.py        # http://127.0.0.1:8001
```

При старте печатает пути к базам, файлам и превью. Если нет ffmpeg — предупреждение (видео собрать не выйдет).

**Терминал 2 — перехват:**

```bash
cd capture
mitmdump -s addon.py --listen-host 127.0.0.1 --listen-port 8000
```

В логе обязательно должна появиться строка:

```
[ydisk] аддон загружен (с авторизацией): ingest -> http://127.0.0.1:8001/api/ingest, ...
```

Её нет → запущен старый/не тот файл.

### Настройка прокси

Прокси `127.0.0.1:8000` выставляется **системно** (macOS: Системные настройки → Сеть → Прокси-сервер; Windows: Свойства сети → Прокси; Linux: настройки окружения/браузера) **либо только в браузере**, с которым ходите на Яндекс.Диск. Схема HTTP, порт 8000.

> Для скачивания файлов прокси не нужен — сервер ходит в сеть напрямую (`ProxyHandler({})`). Прокси нужен только для сбора метаданных и авторизации.

## Сбор данных

1. В браузере через прокси открыть **Яндекс.Диск → Фото**.
2. Нажать «Показывать все» и выбрать фильтр «Скриншоты», чтобы собрать и их.
3. Проверить, что данные появляются: открыть **http://localhost:8001** — должна появиться сетка фотографий.
   - Не появились → смотреть консоли обоих терминалов.
4. **Пролистать ленту вручную сверху до самого конца.** Яндекс подгружает фото лениво: пока не прокрутите — метаданные не придут. Это единственный способ собрать весь список.
5. Параллельно можно открыть **http://localhost:8001/status** — в консоли `mitmdump` строки `[ydisk] перехвачено: кластеров=…, ресурсов=…`.

Превью в галерее появляются **после** скачивания файлов, до этого — пустые плитки, это нормально.

## Скачивание

На **http://localhost:8001/status**:

### Фото

1. Вкладка «Фото».
2. Ввести количество потоков (1–32, по умолчанию 8) → «Применить».
3. Нажать **«Скачать только фото»**.
4. Следить за прогрессом: карточки, полоса, «Качается сейчас», «В ожидании», «Недавно скачано», «Ошибки».
5. При необходимости — «Остановить», «Повторить ошибки».

Файлы кладутся в `server/files/`, открываются из галереи по ссылке `/file/<id>` (HEIC конвертируется в JPEG на лету).

### Видео

1. Вкладка «Видео».
2. При необходимости подкрутить настройки (потоки, размер блока, таймауты, refine, reencode) → «Применить».
3. **«Скачать только видео»** — сервер запросит свежие ссылки по кукам из `auth.db` и запустит `recover.py`.

Требования: рядом с `server.py` лежат `recover.py` и `recover_runner.py`, в PATH есть `ffmpeg`, в `auth.db` есть куки и `sk` (иначе ошибка «нет данных авторизации» — откройте Диск в браузере через прокси и обновите страницу).

### Остановка

После успешного скачивания, **перед выключением mitmdump, обязательно убрать системный прокси обратно.** Иначе весь трафик пойдёт в мёртвый адрес.

## HTTP-интерфейс сервера

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/ingest` | приём JSON photo-get-clusters-with-resources |
| POST | `/api/auth` | куки/sk/UA от аддона → `auth.db` |
| GET | `/api/auth/status` | есть ли авторизация (куки наружу не отдаются) |
| GET | `/` | галерея (сетка по дням) |
| GET | `/chunk` | подгрузка следующих дней |
| GET | `/status` | страница статуса загрузки |
| GET | `/api/items`, `/api/stats` | данные в JSON |
| GET | `/thumb/<id>`, `/file/<id>` | превью / скачанный файл |
| POST | `/api/dl/start\|stop\|threads\|retry-failed` | очередь фото |
| GET | `/api/dl/status` | статус фото |
| POST | `/api/vd/start\|stop\|settings\|retry-failed` | очередь видео |
| GET | `/api/vd/status` | статус видео |

POST принимает только `Content-Type: application/json` (защита от чужих веб-страниц).

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `YDISK_PORT` | `8001` | порт сервера |
| `YDISK_DB` | `server/gallery.db` | база метаданных |
| `YDISK_AUTH_DB` | `server/auth.db` | база авторизации |
| `YDISK_FILES` | `server/files` | папка скачанных файлов |
| `YDISK_THUMBS` | `server/thumbs` | папка превью |
| `YDISK_API_BASE` | `https://disk.yandex.ru` | адрес Яндекса для запроса ссылок |
| `YDISK_INSECURE_SSL` | — | `1` → отключить проверку сертификатов (нужно, если трафик идёт через прокси) |
| `YDISK_SERVER_URL` | `http://127.0.0.1:8001/api/ingest` | куда аддон шлёт данные |
| `YDISK_AUTH_URL` | `<server>/api/auth` | куда аддон шлёт авторизацию |

## Troubleshooting

| Симптом | Причина / решение |
|---|---|
| В ленте нет перехваченных данных | Нет строки `[ydisk] аддон загружен`; не тот файл, не тот порт, или прокси не выставлен |
| В галерее пусто | Ленту не пролистали до конца, либо прокси не настроен на браузер, смотрите логи |
| `HTTP 403` в логах | Протухла сессия/`sk` — обновить страницу Диска в браузере |
| «нет данных авторизации» | Аддон не поймал куки: открыть Диск через прокси и обновить страницу |
| Превью пустые | Нормально: превью создаются после скачивания файлов |
| Видео не собирается | Нет `ffmpeg` в PATH, либо нет `recover.py` рядом с `server.py` |
| Ошибки SSL в Python | Сертификат mitmproxy не установлен/не доверен; либо `YDISK_INSECURE_SSL=1` |
| `pip install requitements.txt` — нет файла | Опечатка: правильно `pip install -r requirements.txt` |
| После остановки mitmdump всё сломано | Забыли убрать системный прокси — убрать |

## Важно

- Перехватываетесь только **своим** трафиком и **своим** аккаунтом Яндекса.
- Значения кук в логи не пишутся, `auth.db` — отдельная база.
- Подписанные ссылки в `items.raw` протухают: для повторного скачивания нужен живой перехват/авторизация.
- Скачивание большого количества файлов — нагрузка на сервера Яндекса; держите разумное число потоков.
